# Terraform

The McHarbor Terraform provider declares McHarbor configuration as code: environments, stacks, roles,
role assignments and API keys, in the same `terraform plan` that creates the hosts. Its source lives
in `src/terraform-provider-mcharbor/`.

| Page | Covers |
|---|---|
| [Resources and data sources](./resources.md) | Every resource and data source, its attributes, import IDs, and the permission keys each operation needs |

## How it works

The provider is a separate Go module on the Terraform plugin framework. Its HTTP client is generated
with `oapi-codegen` from `src/backend/api/openapi.json`, the OpenAPI document McHarbor's router
writes. The provider therefore never hand-writes a request shape. A route that changes shape shows up
as a regenerated client, not as a silent mismatch.

A second generator reads the same document's `x-mcharbor-permission` extension and builds a map from
operation to permission keys. When McHarbor answers 403, the error names the key to grant:

```
McHarbor refused rolesCreate (HTTP 403): Permission denied [err.forbidden]. The API key needs the permission roles.manage
```

## Configuration

| Argument | Environment variable | Meaning |
|---|---|---|
| `endpoint` | `MCHARBOR_ENDPOINT` | Instance root URL, for example `https://mcharbor.example:8705`. Every path already carries its `/api` prefix. |
| `api_key` | `MCHARBOR_API_KEY` | An API key from **Security → API Keys**, sent as `Authorization: Bearer`. Sensitive. |
| `insecure_skip_verify` | none | Accept any TLS certificate. McHarbor ships a self-signed certificate by default; trusting its CA is the better fix. |

The API key acts with the roles it was created with. It needs every permission listed in
[Resources and data sources](./resources.md) for the resources it manages. `api_keys.manage` is
needed to create other keys, and the caller must already hold everything a new key grants.

## Secrets and Terraform state

Terraform stores every attribute in its state in plain text. What reaches state:

- **`mcharbor_environment`**: `ssh_key`, `tls_ca`, `tls_cert`, `tls_key` as configured, and
  `agent_token` for an agent environment. The agent token is returned only in the create response.
  The TLS and SSH values are never read back, so a change made in the UI is not detected.
- **`mcharbor_stack`**: `env_vars`. McHarbor masks secret stack variables on read, and the provider
  keeps the configured value wherever it sees the mask. Prefer `${secret:NAME}` references to the
  secrets vault over literal values in `env_vars`.
- **`mcharbor_api_key`**: `key`, returned only at creation. It is null after `terraform import`.

- **`mcharbor_secret`**: never the value. It is supplied write-only (`value_wo`, Terraform 1.11+)
  or generated by McHarbor, and a rotation is requested by bumping `value_wo_version`.
- **`mcharbor_storage_location`**: never the credentials. The `*_wo` attributes and `config_wo` are
  write-only and re-sent when `credentials_version` changes.

Roles, role assignments, schedules, update policies, alert rules and backup plans carry no secret
material.

Treat the state backend as holding these secrets: encrypted at rest, with access limited to the
people who may hold them.

## Status

Phases 1 to 3: the Tier 1 and Tier 2 resources (environments, stacks, roles, role assignments,
API keys, secrets, schedules, update policies, alert rules, storage locations, backup plans), the
Tier 3 resources (workflows as a JSON file reference, plugins pinned to a catalog version), import
for each, and eight data sources, among them containers, images, the app catalog and the plugin
catalog. Not yet built: the desired-state resource, and publication to the Terraform registry.
Until it is published, the provider is installed from a local build with a `dev_overrides` block.
See the module's `README.md`.
