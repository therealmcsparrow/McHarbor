# Add an app to the catalog

An app in the Store is one JSON file under `apps/`. The official catalog that every McHarbor
reads, `https://www.mcharbor.eu/catalog/apps/index.json`, is a single document that carries
every one of those files inline. Adding an app is therefore three steps: write a spec line,
generate the entry, rebuild the index and upload it.

Entries are generated rather than hand-written. The generator validates the spec and writes the
file in the catalog's house style, so a new entry is byte-compatible with the existing ones.

## 1. Write the spec

A spec file holds one JSON object per line (`.jsonl`). Blank lines and lines starting with `//`
are skipped.

| Field | Required | What it is |
|---|---|---|
| `slug` | yes | Lowercase words joined by `-`; also the file name. Refused when the catalog already has it, unless you pass `--force` |
| `name`, `category`, `website` | yes | Card title, Store category, project link |
| `description` | yes | At most 160 characters |
| `image` | yes | With a tag (`:latest` counts). An image without one is refused |
| `logo` | no | A URL, or a name from the dashboard-icons set; the slug is used when it is absent |
| `docsUrl` | no | The **Documentation** link; defaults to `website` |
| `ports` | no | `[host, container, protocol]` triples, integers; protocol defaults to `tcp` |
| `volumes` | no | `[host, container, readOnly]`; both paths absolute. Host paths start `/opt/appdata/<slug>` |
| `env` | no | `[key, default, description, secret]`. `TZ` (`Etc/UTC`) is always added first. A default may not contain `{{` |
| `minMemory` | no | Shown on the card, such as `"1GB"` |
| `stack` | no | Generates a compose file with companion containers (`postgres`, `mysql`, `mariadb`, `redis`, `extra`) and fixed `appEnv` values |
| `composeOverrideRaw` | no | A compose template used as is, for what `stack` cannot express: host networking, devices, capabilities, privileged mode |

Without `stack` or `composeOverrideRaw`, the Store builds the compose file from the image,
ports, volumes and environment alone.

## 2. Compose templates

A `composeOverrideRaw` template is filled in at install time:

| Placeholder | Becomes |
|---|---|
| `{{serviceName}}`, `{{containerName}}`, `{{projectName}}` | The stack name the operator chose |
| `{{appDataPath}}` | `/opt/appdata/<stack name>` |
| `{{image}}` | The image, at the tag being installed |
| `{{ports}}`, `{{volumes}}`, `{{environment}}` | The whole `ports:` / `volumes:` / `environment:` block, as set in the install wizard |
| `{{environmentMap}}` | The environment as a `KEY: value` map instead of a list |
| `{{networks}}`, `{{networkMode}}` | The network chosen in the wizard |
| `{{env.KEY}}` | That variable's value, quoted for YAML |
| `{{envRaw.KEY}}` | That variable's value, unquoted |

In a list item (`- …`), only the **first** `{{env.KEY}}` on the line is substituted, and the
whole item is quoted. Write `- {{env.RADIO_DEVICE}}:/dev/ttyRCP`, not
`- {{env.DEVICE}}:{{env.DEVICE}}`: the second placeholder would reach Docker as literal text.

## 3. Generate, index, check

```bash
node scripts/apps/generate-entries.mjs my-apps.jsonl            # validate only
node scripts/apps/generate-entries.mjs my-apps.jsonl --write    # writes apps/<slug>.json and mnt/app-catalog/<slug>.json
node scripts/apps/build-index.mjs apps                          # rewrites apps/index.json
node scripts/apps/build-index.mjs apps --check                  # "apps/index.json is current (N apps)"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/sanity/app-catalog/check.ps1
```

The index build refuses a file whose `slug` does not match its file name, more than 5,000 apps,
or an index over 8 MiB, because every McHarbor refuses a remote catalog past those limits.

`mnt/app-catalog/` is the dev container's local catalog; it takes the app files, not the index.

## 4. Publish

Upload `apps/index.json` to `https://www.mcharbor.eu/catalog/apps/`. An installation picks it up
on its next catalog sync, or straight away with **Sync** in the Store
(`store_apps.manage`).

## Worked example: `hass-otbr`

[hass-otbr-docker](https://github.com/ownbee/hass-otbr-docker) runs Home Assistant's OpenThread
Border Router add-on as a stand-alone container. It needs host networking, privileged mode, two
capabilities and two devices, so it takes a `composeOverrideRaw`:

```yaml
# Generated by McHarbor App Store
services:
  {{serviceName}}:
    image: {{image}}
    container_name: {{containerName}}
    restart: unless-stopped
    privileged: true
    network_mode: host
    cap_add:
      - SYS_ADMIN
      - NET_ADMIN
    devices:
      - {{env.RADIO_DEVICE}}:/dev/ttyRCP
      - /dev/net/tun:/dev/net/tun
{{volumes}}
{{environment}}
    logging:
      driver: json-file
      options:
        max-file: "3"
        max-size: "1m"
```

The radio's host port is one variable, `RADIO_DEVICE`, mapped to a fixed path inside the
container, and the app's own `DEVICE` defaults to that path. That keeps to the one-placeholder
rule above and leaves the operator a single value to change. `ports` is empty because the
container uses the host network: the REST API (`OTBR_REST_PORT`, 8081) and web UI
(`OTBR_WEB_PORT`, 7586) listen on the host directly.

What the catalog cannot do for an app like this is prepare the host. The Thread border router
needs IPv6 on the LAN and the host's kernel settings (`net.ipv6.conf.all.forwarding = 1`,
`net.ipv6.conf.all.accept_ra = 2` and the others in the project README), and the radio needs
OpenThread RCP firmware. The entry's **Documentation** link points at that setup.
